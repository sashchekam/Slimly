# Событие аналитики

Источник правды — код. Таблица `ANALYTICS.md` собирается из него скриптом,
руками её не правят.

## Где живут события

У каждого модуля свой объект аналитики в одном файле:

```
Modules/Features/CompressFeature/Sources/CompressAnalytics.swift
App/Sources/AppAnalytics.swift
```

Общую аналитику приложения (`any AnalyticsService`) он получает параметром
конструктора и складывает поверх неё свой словарь событий. Сам SDK ему
не виден: Firebase знает только `SlimlyFirebase`.

```swift
import SlimlyCore

/// Аналитика сжатия.
struct CompressAnalytics: FeatureAnalytics {
    static let scope = "compress"

    let analytics: any AnalyticsService

    /// Пользователь выбрал файлы и пошёл дальше.
    func didPickFiles(_ count: Int) {
        track("files_picked", ["count": .int(count)])
    }
}
```

Первая строка документации метода уезжает в реестр колонкой «что значит» —
пиши её как объяснение события, а не как пересказ имени.

## Общие шаги — одна воронка

Экраны выбора файлов, обработки и итога живут в `SlimlyMediaFlow` и одни
на все инструменты. События у них тоже одни: `FlowAnalytics` со своим
префиксом `flow` и параметром `tool` («compress», «convert_photo», «scan»).
Своей копии этих событий фича не заводит — иначе одна воронка была бы
описана четыре раза, а в отчёте её пришлось бы склеивать руками.

В аналитике фичи остаётся только то, чего у соседа нет: степень сжатия
в `CompressAnalytics`, съёмка страниц и границы листа в `ScanAnalytics`.
Инструмент, которому принадлежит шаг, задаёт резолвер:

```swift
let flow = FlowAnalytics(analytics: analytics, tool: .compress)
```

## Конвенция

- Имя события: `<объект>_<действие>` в прошедшем времени, строчной латиницей
  через подчёркивание. Префикс модуля добавляется сам из `scope`, в `track`
  его не пишут.
- Полное имя (`scope` + имя) — не длиннее 40 символов, только буквы, цифры
  и подчёркивания, первый символ буква. Firebase молча теряет всё остальное.
- Параметр — существительное без префикса модуля: `count`, `source`,
  `format`, `duration_ms`. Перед тем как завести новый, загляни
  в `ANALYTICS.md`: одно и то же не должно ездить как `count` и `amount`.
- Значение параметра — `AnalyticsValue`. Флаг едет числом, строка режется
  до ста символов, всё это делает `SlimlyFirebase`.
- Имена параметров пишутся литералами прямо в `track(...)`: реестр собирается
  разбором кода, и ключ, спрятанный в переменную, в таблицу не попадёт.
  Значение — наоборот, любое выражение.
- Строковое значение параметра — такой же код, как имя события: `audio_extraction`,
  а не `audioExtraction` и не «Извлечение звука». Подписи интерфейса
  в отчёт не уезжают, их переписывают, а разрез по ним ломается.
- Персональных данных в параметрах нет: ни путей к файлам, ни имён,
  ни адресов ссылок целиком.

## Свойства пользователя

Свойство — это срез, по которому потом режется отчёт: доступ к медиатеке,
дошёл ли человек хоть раз до сохранённого файла. Живёт до переустановки
и приезжает со всеми следующими событиями, поэтому заводить его стоит
только под вопрос «кого с кем сравниваем», а не про каждое действие.

Ключ объявляется расширением `AnalyticsUserProperty` рядом с тем, кто его
ставит, — как `StorageKey` и `RemoteConfigKey`:

```swift
public extension AnalyticsUserProperty {
    static var mediaAccess: AnalyticsUserProperty { AnalyticsUserProperty("media_access") }
}
```

В `ANALYTICS.md` свойства не попадают: реестр собран из событий.

## Как подключить к экрану

1. В резолвер фичи приходит общая аналитика приложения — явным параметром,
   как остальные зависимости: `CompressFeature.resolver(analytics:...)`.
   Свои объекты (`CompressAnalytics`, `FlowAnalytics`) фича собирает поверх
   неё сама, один раз на резолвер.
2. ViewModel получает готовую аналитику модуля в `init` и зовёт её методы.
   View аналитику не дёргает — событие это следствие действия, а не отрисовки.
3. `AppContainer` про события фичи ничего не знает: он отдаёт общий
   `AnalyticsService` и на этом заканчивает.

## Чек-лист перед завершением

- [ ] Событие объявлено методом аналитики модуля, а не строкой на месте вызова.
- [ ] У метода есть строка документации: она попадёт в реестр.
- [ ] Имена параметров сверены с `ANALYTICS.md`.
- [ ] Событие общего шага заведено в `FlowAnalytics`, а не скопировано
      в четыре фичи.
- [ ] `swift Tools/AnalyticsRegistry.swift` перезаписал реестр, диff вошёл
      в коммит. Скрипт же висит фазой сборки в режиме `--check` и валит
      сборку, если реестр отстал.
- [ ] `swiftlint lint --strict --quiet` молчит.
- [ ] Новые параметры зарегистрированы в консоли Firebase как custom
      dimensions — иначе они приезжают в события, но не появляются в отчётах.
